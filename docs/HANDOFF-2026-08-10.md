## 2. Architecture rulings — TR-1 … TR-4 (TDD §0.7 / §0.7a). Settled. Do not reopen.

- **TR-1 — one canonical *derivation*, not one canonical field.** A single exported
  `getCarouselEdges()` in the neutral `lib/server/analysis/carousel/` module (shipped by #180). Two
  fields may *carry* a slide count; **exactly one expression computes it.** The cross-assertion is
  mandatory as the regression detector for TR-1 itself.
- **TR-2 — duplication is the transmission mechanism; delete duplicates, do not patch them.** Both
  file-local `getCarouselChildren()` copies deleted. **Doc comments are not guards** — prefer illegal
  states unrepresentable.
- **TR-3 — the `carouselItemCount === LaterSlideReach.slideCount` cross-assertion is mandatory** on a
  null-`node` fixture, alongside the "nothing changed for the no-null-node case" test.
- **TR-4 — the slide-manifest header states NO total.** `totalPartsBeforeCap` /
  `mediaPartsTotalBeforeCap` are **deleted, not renamed**. The truncation note's gate widens to
  `mediaPartsTruncated === true || (carouselItemCount != null && parts.length < carouselItemCount)` and
  **names no number**. The boolean `truncated` survives **because a boolean cannot be rendered as a
  count**. Structural detector: the prompt must contain **exactly one** `/\d+ slides?/` token. Gaps in
  the manifest are deliberately **not** explained to the model.

> **TR-4's diagnosis is the one worth carrying.** #182 read as a copy bug. It was not: `formatMediaType()`
> already renders `carousel (N slides)` canonically one block higher, so the manifest header was a
> **second expression rendering a quantity that was already canonical** — TR-1's failure class, surviving
> only because the field's *name* claimed it was about the cap rather than about slides.

## 8. Process lessons — the highest-value section, do not compress it away

1. **Review found every substantive defect; the suite found none.** §0. Fifth consecutive session.
2. **Re-run mutation proofs; never read them.** §0. **Four vacuous assertions across one PR's life** —
   three fixed, one still latent. Judge the killing assertion, not the kill count. **The `?? ""` /
   `?? []` fallback in front of a negative assertion is the reliable tell**, because it makes the
   subject empty and the assertion tautological. This is the session's most repeated defect class.
3. **Duplication is the transmission mechanism.** A bug fixed in `reach.ts` stayed live in two other
   files because the helper had been copied. TR-2 exists because of this. **Delete duplicates, do not
   patch them.**
4. **Rebase before approving.** Separately-green branches prove nothing about the combination. #184's
   re-review ran on the merged tree and said so explicitly.
5. **Specialists correcting the brief is the system working — it happened five times:** the
   table-width premise, #142's blockers, the `PERFORMANCE_DATA_ABSENT` naming, #182's diagnosis, and
   the stale #175. **Briefs asserted from memory while PMs are actively filing tickets are a reliable
   source of churn.** Verify the brief against the repo before dispatching from it. (This handoff was
   written to that rule; §11 records what failed the check.)
6. **The `AGENTS.md` shell-redirection ban held all session — zero violations**, against two in the
   prior session. What changed: every agent was briefed **explicitly** — Edit/Write tools only; revert
   mutations **with the Edit tool, never `git checkout --`**; commit before mutation testing. Keep
   briefing it explicitly.
7. **A PR body is a commit message. Review it like one.** This session **rewrote two squash bodies at
   merge time** — **#179**'s (a stale rationale) and **#184**'s (it still described the *rejected*
   widening approach as though it had shipped). #184's **final blocker was its description, not its
   code**: the review closed every code blocker and held the PR on the body alone. That body had
   carried **three** inaccurate claims over its life; other PRs this session claimed a type probe that
   did not exist and claimed the parser rejects extra fields when it silently drops them.
   **Two consequences, both cheap to act on:** (a) the body outlives the PR as permanent repo history,
   so an inaccurate one is a durable false record, and (b) a reviewer may take it on trust and skip the
   check it describes. **Make "does the body match the diff?" an explicit review step, and re-read the
   squash message in the merge dialog before confirming.**
8. **Rulings and implementations that land in different PRs will auto-close the ticket early.** #182
   (§7). If a ticket's body says "closes when X merges", the closing keyword must live on **X**.
